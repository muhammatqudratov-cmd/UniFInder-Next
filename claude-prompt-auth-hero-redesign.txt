Context: the Login/Signup page (`/account/join`) hero is rendered by the shared `withLayoutBasic` HOC, not by `pages/account/join.tsx` itself. Two problems, both confirmed by reading the live code directly:

1. Background mismatch: in the `memoizedValues` switch inside `libs/components/layout/LayoutBasic.tsx`, the `/account/join` case is the ONLY route (besides `/cs`, which doesn't render this hero at all) that still sets `bgImage = '/img/banner/korea2.jpg'`. That value gets applied as an inline `style={{ backgroundImage: url(...), backgroundSize: 'cover' }}` directly on the `.header-basic` wrapper, which completely covers the dark gradient background (`linear-gradient(135deg, #15140f 0%, #1c2620 50%, #1a2230 100%)`) that every other page's hero uses (University, Agent, My Page, Community, Community Detail, Member all already have `bgImage = ''` for exactly this reason). This is why the Login/Signup hero currently looks different from every other page.
2. No rich hero markup: `/account/join` has no dedicated branch in the hero's JSX ternary chain, so it falls into the generic fallback branch and only ever renders a bare `<strong>Login/Signup</strong><span>Authentication Process</span>` — no eyebrow pill, no paragraph, no badges, no graphic.

This change: (a) removes the stock photo so the hero falls back to the same dark gradient background used by every other page, (b) adds a dedicated hero branch for `/account/join` with an eyebrow pill, a heading with a coral-colored "/" between "Login" and "Signup", a description paragraph, two badge chips, and a small graphic (lock icon + floating decorative shapes) on the right, mirroring the structure already used for the `/community` and `/member` hero branches, and (c) adds a CSS keyframe animation so the small decorative shapes gently float up and down. This is presentational-only — no GraphQL, no Apollo, no existing state/handlers touched. `setAuthHeader(true)` and the `authHeader` state are untouched (still controls the `.auth` modifier class).
