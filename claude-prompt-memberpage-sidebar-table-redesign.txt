Context: redesign the Member Page's left profile sidebar card and the right-side "Universities" listing table to match a cleaner, more minimalistic reference layout, using the site's existing brand palette (coral #e8856a, dark #1c1b18, green #5a8a52/#3b6d11/#eaf3de, cream #e8e0d5/#f5f3ef, muted gray #8e8c83) — not generic blue/gray Material colors. The page structure/layout sizing (widths, heights, margins of the big containers) stays untouched to avoid breaking the page; only colors, typography, badge/pill shapes, spacing inside elements, and a couple of small presentational additions change.

Four files are touched:
1. `scss/pc/member/memberPage.scss` — sidebar card visual restyle (CSS only).
2. `scss/pc/member/memberUniversities.scss` — listing table visual restyle (CSS only).
3. `libs/components/mypage/UniversityCard.tsx` — replaces the row's two hardcoded inline `sx` color overrides (which always rendered the same blue regardless of actual status) with a conditional className based on the existing `university.universityStatus` value, so CSS can finally color ACTIVE green / INACTIVE gray / DELETE red — this only changes which className is applied, not any data, query, or business logic. Also adds a fallback image path when `universityImages[0]` is empty, mirroring the exact same fallback pattern already used in the sibling component `libs/components/university/UniversityCard.tsx`.
4. `libs/components/member/MemberUniversities.tsx` — adds a small "{total} listings" label next to the "Universities" title, reusing the `total` value that is already fetched and already displayed elsewhere on the same page (`.total-result`) — no new query, no new state, just rendering an existing variable in one more place.

No GraphQL/Apollo queries, mutations, or event handlers are added, removed, or changed in any file.
