Context: precise redesign of the MyPage hero (the banner area rendered above the `<Component />` slot by `withLayoutBasic` for `router.pathname === '/mypage'`), matching the attached reference screenshot exactly. Currently `/mypage` falls into the generic "plain" branch in `libs/components/layout/LayoutBasic.tsx` (`memoizedValues` case `/mypage` just sets `title: 'my page'`, `desc: 'Home / For Rent'`, `bgImage: '/img/banner/type/incheon.jpg'`), rendering a bare dark-overlay banner with a title/subtitle. This is a visual-only change to the hero banner: do NOT touch `pages/mypage/index.tsx`'s category routing, any of the `MyProfile`/`MyMenu`/etc. components below the hero, or any mutation/query logic anywhere in the app. Only edit `libs/components/layout/LayoutBasic.tsx` and `scss/pc/main.scss`.

Three things in the screenshot are grounded in real, already-available data — use them as-is, no new query needed (the component already has `user` via `useReactiveVar(userVar)`):
1. Name ("Marco") → `user?.memberNick`
2. ID-style line ("01057482425") → `user?.memberPhone`
3. Role badge ("AGENT") → `user?.memberType` (real enum field: `USER` / `AGENT` / `ADMIN`)
4. "Listings" stat (12) → `user?.memberUniversities` (the real field for how many universities this member manages/follows)
5. "Followers" stat (248) → `user?.memberFollowers ?? 0`
6. Avatar → reuse the existing fallback convention: `user?.memberImage ? \`${REACT_APP_API_URL}/${user.memberImage}\` : null`, falling back to a plain person icon when there's no uploaded image (do not invent a new default image asset)

One thing in the screenshot has no backing field — flag explicitly rather than inventing logic:
- "98% Response" — there is no response-rate field anywhere on `Member`. Hardcode `98%` as a static, clearly-decorative placeholder stat, exactly like the Community hero's static "INU" precedent.
