Context: the reference design for the Community sidebar shows a real post count next to every tab label ("Free Board 2", "Recommendation 2", "News 2", "Humor 1"), but the current implementation only shows a count near the title of whichever tab is currently active, and the sidebar tab labels themselves are plain text with no number. This is the one concrete gap between the current app and the reference screenshot.

Why this needs one extra step beyond pure CSS: the existing `GET_BOARD_ARTICLES` query only returns a count (`metaCounter[0].total`) for the single category passed in `input.search.articleCategory`. There is no existing query that returns counts for all 4 categories at once. The fix below does NOT add any new GraphQL operation, resolver, or schema field — it reuses the exact same `GET_BOARD_ARTICLES` query that's already used for the main list, just called 3 more times with `limit: 1` and a different `articleCategory`, purely to read `metaCounter[0].total` for each board. No mutations, no new types, no change to the main list query/variables/refetch logic.

## `pages/community/index.tsx`

1. Add three extra lightweight `useQuery` calls (one per non-list-purpose count), right after the existing `boardArticlesData` query block. Each uses the same `GET_BOARD_ARTICLES` query, `limit: 1` (we only need the count, not the list), and a fixed category:

```tsx
const { data: freeCountData } = useQuery(GET_BOARD_ARTICLES, {
	fetchPolicy: 'cache-and-network',
	variables: { input: { page: 1, limit: 1, sort: 'createdAt', direction: 'ASC', search: { articleCategory: 'FREE' } } },
});
const { data: recommendCountData } = useQuery(GET_BOARD_ARTICLES, {
	fetchPolicy: 'cache-and-network',
	variables: { input: { page: 1, limit: 1, sort: 'createdAt', direction: 'ASC', search: { articleCategory: 'RECOMMEND' } } },
});
const { data: newsCountData } = useQuery(GET_BOARD_ARTICLES, {
	fetchPolicy: 'cache-and-network',
	variables: { input: { page: 1, limit: 1, sort: 'createdAt', direction: 'ASC', search: { articleCategory: 'NEWS' } } },
});
const { data: humorCountData } = useQuery(GET_BOARD_ARTICLES, {
	fetchPolicy: 'cache-and-network',
	variables: { input: { page: 1, limit: 1, sort: 'createdAt', direction: 'ASC', search: { articleCategory: 'HUMOR' } } },
});
```

Then derive plain numbers from them (place right after the four hooks above):

```tsx
const freeCount = freeCountData?.getBoardArticles?.metaCounter[0]?.total ?? 0;
const recommendCount = recommendCountData?.getBoardArticles?.metaCounter[0]?.total ?? 0;
const newsCount = newsCountData?.getBoardArticles?.metaCounter[0]?.total ?? 0;
const humorCount = humorCountData?.getBoardArticles?.metaCounter[0]?.total ?? 0;
```

Important: these 4 new hooks are entirely separate from the existing `boardArticlesData`/`boardArticlesRefetch`/`searchCommunity` query — do not merge them, do not change `onCompleted`, do not touch `tabChangeHandler`, `paginationHandler`, or `likeArticleHandler`. They exist solely to read counts for the sidebar badges.
