Context: "Add University" form has three leftover real-estate-template dropdowns with placeholder/meaningless numbers (Faculties only goes to 5; Capacity is literally `[1,2,3,4,5]` stored in a variable named `bed` — leftover from a "number of bedrooms" field; Campus Size pulls from a shared `universityCampusSize` array in `libs/config.ts` whose values `[0,25,50,75,100,125,150,200,300,500]` are leftover real-estate apartment-size numbers in m², nowhere close to real university campus sizes). This prompt replaces all three with research-grounded values. Sources used (all real, cited):

- Capacity (student enrollment) bounds: POSTECH ≈ 3,425 students (small, research-focused) [edurank.org/uni/pohang-university-of-science-and-technology]; Seoul National University = 28,378 students [en.snu.ac.kr/about/overview/fact]; Korea University ≈ 36,000–39,000 students (28,000+ undergrad, 11,000+ grad) [en.wikipedia.org/wiki/Korea_University]; Yonsei University 40,000+ students (main + Mirae campus) [en.wikipedia.org/wiki/Yonsei_University].
- Campus Size (m²) bounds: Sogang University ≈ 242,091 m² (59.6 acres) [en.wikipedia.org/wiki/Sogang_University]; Korea University Sejong campus = 425,130 m² [en.wikipedia.org/wiki/Korea_University]; Korea University Seoul campus = 946,177 m² (~94 ha) [en.wikipedia.org/wiki/Korea_University]; POSTECH campus ≈ 1,529,000 m² (378 acres) [panda-admission.com/blog — POSTECH campus size].

These give 5 round, increasing brackets for each field, each one matching a real cited university. Both `universityCapacity` and `universityCampusSize` are plain `number` fields on `UniversityInput` (`libs/types/university/university.input.ts`) and are rendered elsewhere as raw single numbers ("{value} students", "{value} m2" — see `UniversityCard.tsx`, `pages/university/detail.tsx`). So each dropdown option is labeled as a range but stores the range's **lower bound** as the actual numeric value — this preserves the existing single-number storage/display everywhere else, with zero schema or query changes.
