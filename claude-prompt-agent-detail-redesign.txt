Context: redesign the Agent detail page (`/agent/detail`, file `pages/agent/detail.tsx`) hero + profile block + portfolio header to match the new reference design (dark gradient hero with "VERIFIED AGENT" badge and breadcrumb, a white profile card overlapping the hero bottom with avatar/name/phone/stats/Contact button, and a "PORTFOLIO / Listed universities" header with decorative filter pills above the existing university card grid).

Ground rules for this change:
- No GraphQL query/mutation is added, removed, or modified. No existing handler's behavior changes.
- `universityTotal` and `commentTotal` are REAL data already fetched on this page (server-side counts) — used for the "Listings" and "Reviews" stats. There is no real "rating" field anywhere in the schema, so "Rating" is a static placeholder (`4.8★`) purely for visual match — this is an intentional, explicitly-approved design liberty, not invented business data.
- There is no "verified"/"approved" field in the schema either, so "VERIFIED AGENT" is a static decorative badge, not bound to any real verification logic — also an explicitly-approved design liberty.
- The "All / Dormitory / Scholarship" filter pills above the card grid are purely visual (no working filter logic is added) — "All" is always shown active. Wiring real filtering is out of scope for this change.
- The breadcrumb's agent name ("Home / Agents / Marco") IS real data — it requires lifting the already-fetched agent name from the page up into the shared `LayoutBasic` header via a small new React Context (`AgentHeroNameContext`). This is new presentational-only plumbing (a context + one `useState` + one `setAgentHeroName(...)` call after data is fetched) — it does not touch any GraphQL/Apollo logic, only forwards an already-fetched display string.
