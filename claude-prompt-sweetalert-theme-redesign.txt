Context: pure CSS change, zero logic touched. Every popup/alert on the site (the "Can not write review for yourself" error, the like-button success toast, confirm dialogs, etc.) is generated by the `sweetalert2` library through helper functions in `libs/sweetAlert.ts` (`sweetErrorHandling`, `sweetTopSuccessAlert`, `sweetMixinSuccessAlert`, `sweetTopSmallSuccessAlert`, `sweetConfirmAlert`, etc.). Right now these render with SweetAlert2's stock default look (default red ring/cross icon, default fonts, default button shapes) because no custom theme is applied — confirmed by reading `libs/sweetAlert.ts` in full: every call only sets `icon`, `title`/`text`, `timer`, and occasionally `confirmButtonColor` — there is no `customClass` or site CSS targeting SweetAlert2's own classes anywhere in the codebase.

The fix: add one global SCSS block that restyles SweetAlert2's own class names (`.swal2-popup`, `.swal2-icon`, `.swal2-title`, `.swal2-confirm`, `.swal2-toast`, etc.) to match this site's look (Poppins font, `#1c1b18` dark text, `#e8856a` coral for errors, `#5a8a52` green for success — the same green already used for the Dormitory/Scholarship "available" pills elsewhere in this codebase, rounded corners, soft shadows). This is added to `scss/app.scss`, which is the one global stylesheet imported in `pages/_app.tsx` and applies site-wide automatically — so every alert everywhere (login, comments, likes, reviews, etc.) gets the new look without touching a single call site or any of the `Swal.fire()` logic, messages, icons, or timers in `libs/sweetAlert.ts`.

Some properties use `!important`: SweetAlert2 injects its own default stylesheet into the page at runtime (when the first alert fires), which can load after Next.js's compiled global CSS and would otherwise silently override a plain CSS fix — `!important` here is necessary to reliably win against that, not a design choice.
