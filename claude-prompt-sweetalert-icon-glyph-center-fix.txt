Context: follow-up fix to the SweetAlert2 icon badge in `scss/app.scss`. Latest screenshot shows the ✕ glyph inside the coral-outlined badge is not visually centered in its box (sits offset, not in the middle).

Root cause: the glyph is drawn via `::after { content: '\2715'; }` (the heavy multi-stroke ✕ character, U+2715) and inherits `font-family: $font` (Poppins, a custom display webfont) from the popup. Poppins' glyph metrics for that specific symbol are not evenly balanced inside its own em-box, and the pseudo-element's default `line-height` (inherited, larger than the glyph itself) adds extra space unevenly above/below the character — so even though the parent badge centers the pseudo-element's box via flexbox, the glyph drawn inside that box still looks off-center. Fix: (1) switch the error glyph to the lighter, more evenly-balanced multiplication-sign character `×` (U+00D7), which standard sans-serif font metrics center far more predictably than the heavy ✕; (2) explicitly set `line-height: 1` and a neutral system sans-serif font on all three glyphs (`::after` for error/success/question) so the pseudo-element's box tightly wraps the character with no extra ascender/descender space, instead of inheriting Poppins' uneven metrics for these specific symbols. The badge's size, border, color, and position are untouched — this only changes how precisely the glyph sits inside the already-correctly-positioned box.

Pure CSS, no JSX, no `libs/sweetAlert.ts`, no call-site logic changes.
