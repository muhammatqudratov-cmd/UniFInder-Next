Context: follow-up fix to the SweetAlert2 theme in `scss/app.scss`. User confirmed the icon badge is sitting right up against / touching the popup card's left edge, instead of staying inset 24px like the rest of the layout (title margin, popup padding) assumes.

Root cause: our `.swal2-icon { ... left: 24px !important; ... }` rule is a bare `.swal2-icon` selector with specificity (0,1,0). SweetAlert2 injects its own default stylesheet into the page at runtime — the same mechanism that earlier caused the top accent bar's `overflow: hidden` to lose a cascade tie. If SweetAlert2's own bundled `.swal2-icon` positioning rules happen to load after ours and tie on specificity for a given property, theirs can win regardless of our `!important` (ties between two `!important` declarations are broken by source order, and their runtime-injected stylesheet loads after our compiled CSS). The robust fix already established in this codebase for this exact failure mode is to stop relying on the cascade race: raise our rule's specificity so it wins unconditionally. Moving the `.swal2-icon` rule to be nested inside `.swal2-popup` (making the compiled selector `.swal2-popup .swal2-icon`, specificity 0,2,0) makes it outrank any bare `.swal2-icon` rule from SweetAlert2's own stylesheet regardless of load order.

Pure CSS restructuring — the rule moves location and its selector becomes a descendant selector, but every property and value inside stays identical. No JSX, no `libs/sweetAlert.ts`, no call-site logic changes.
