Context: visual bug, CSS-only fix, no JSX/logic change. On the Agents list page (`/agent`), the agent card's bottom row (name + "Agent" label on the left, eye-icon + view-count + heart-icon + like-count on the right) overflows past the card's right edge — the like-count number gets pushed outside the card and is clipped/invisible. This is the same root-cause pattern already fixed on the My Favorites page (`myFavorites.scss`): the card has a fixed width, but the row inside it has no `overflow`/shrink constraints, so when both the name block and the icon/count block need their full natural width, they exceed the available space.

Confirmed in `scss/pc/general.scss`, the `.agent-general-card` rule (rendered by `AgentCard.tsx`):
- Card width is fixed at `200px`.
- `.agent-desc` (padding `14px 16px 16px`) lays out `.agent-info` (name + role) and `.buttons` (eye icon, view count, heart icon, like count) side by side with `justify-content: space-between`, but neither child has any `flex-shrink`/`min-width`/`overflow` constraint.
- `.buttons` renders two MUI `IconButton`s, which have a fairly large default click-target padding — combined with `.agent-info`'s natural width, the row's total content width exceeds the ~168px of usable space inside the card, pushing the like-count number past the right edge.

Replace with:

```scss
	.agent-desc {
		margin-top: 0;
		padding: 14px 12px 16px 16px;
		display: flex;
		flex-direction: row;
		justify-content: space-between;
		align-items: flex-start;
		overflow: hidden;
		.agent-info {
			display: flex;
			flex-direction: column;
			min-width: 0;
			flex: 1 1 auto;
			overflow: hidden;
			strong {
				color: #1c1b18;
				font-family: $font;
				font-size: 15px;
				font-style: normal;
				font-weight: 700;
				line-height: normal;
				cursor: pointer;
				white-space: nowrap;
				overflow: hidden;
				text-overflow: ellipsis;
			}
			span {
				margin-top: 2px;
				color: #8e8c83;
				font-family: $font;
				font-size: 12px;
				font-style: normal;
				font-weight: 500;
				line-height: normal;
			}
		}
		.buttons {
			width: auto;
			flex-shrink: 0;
			display: flex;
			flex-direction: row;
			justify-content: center;
			align-items: center;
			gap: 1px;

				padding: 3px;
			}

				height: 17px;
				cursor: pointer;
				color: #8e8c83;

				}
			}

				font-size: 12px;

```

What changed and why:
- `.agent-desc` gets `overflow: hidden` as a safety net so nothing can visually spill past the card's rounded corners.
- `.agent-info` gets `min-width: 0; flex: 1 1 auto; overflow: hidden;` so it's allowed to shrink instead of forcing `.buttons` out of the card; its name (`strong`) truncates with an ellipsis if a very long agent name doesn't fit, instead of pushing the icon row off the edge.
- `.buttons` gets `flex-shrink: 0` so the icon/count row keeps its own size and is never the thing that gets crushed, plus a smaller `gap`, reduced `.MuiIconButton-root` padding (MUI's default IconButton padding is too large for this 200px-wide card), and slightly smaller icon/text sizes — mirroring the exact fix already applied to `myFavorites.scss` for the same overflow problem.
- No color, font-family, font-weight, or border-radius values changed — this is purely a spacing/overflow fix, not a redesign.

Do not change anything else — no other selector, no JSX, no click handler, no query/mutation, no other card type.
