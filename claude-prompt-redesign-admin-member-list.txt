Context: visual/CSS redesign of the Admin "Member List" page (sidebar + header + table) to match a reference design ("Membership Console" dark-sidebar style). This is presentation-only: every data fetch, query, mutation, state variable, handler, and route stays exactly as-is. The only behavioral-looking changes are pure presentational mappings computed from fields that are already fetched (e.g. choosing a badge color from `member.memberType`/`member.memberStatus`, or deriving avatar initials from `member.memberNick`) — no new GraphQL calls, no new backend logic, no renamed business fields.

Two elements visible in the reference design are intentionally NOT included, because building them would require inventing data or behavior that doesn't exist in this codebase:
- The "+ Add member" button (no create-member mutation/flow exists anywhere in the project).
- The "Total Members / Active / Flagged" stat cards at the top (those require aggregate counts across all members regardless of the current tab filter, which is not fetched by the existing `GET_ALL_MEMBERS_BY_ADMIN` query — only the currently selected tab's filtered total is available via `metaCounter`).
If wanted later, both would need a new dedicated query/mutation — out of scope here.
